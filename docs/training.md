# Setup recordings: v0.1 treatment

The attached developer playbook supplied seven Claude-specific narrated MP4s and poster images. They remain in the original ZIP; they are not included as authoritative setup instructions in this release.

Written, source-linked setup steps are the current onboarding path. No Copilot recordings have been fabricated, relabelled or claimed as completed.

| Original clip | Replacement brief |
| --- | --- |
| toolkit | Shared workload prerequisites, then separate Claude, Copilot CLI and VS Code install routes; record current versions |
| signin | Separate agent login and platform identity; inspect credential paths and verify approved DEV |
| dataverse | Administrator enables the actual registered client for each selected tool/surface; demonstrate separate read-only checks |
| plugins | Current shared CLI marketplace, host-specific VS Code route, maturity labels and duplicate-install prevention |
| repo | AGENTS.md as canonical rules, instruction bridges, shared skills, public MCP example and approved placeholders |
| project | Neutral per-client discovery workspace, approved context and product-owner-reviewed outputs |
| agent | Correct Copilot Studio agent type, experimental/successor distinction, source validation and human publication boundary |

## Recording acceptance

- One clear task and tool/host/version label per clip.
- Use synthetic/demo content with no visible tenant secrets, tokens or client information.
- Show the final read-only/setup evidence, not just installation success.
- Include captions and a matching transcript; record date and review owner.
- Capture command approval behavior without real destructive or TEST/PROD actions.
- Technical reviewer verifies the clip against the written adapter.
- Remove/retire stale clips when instructions change.

Replacement recordings require a real approved demonstration environment and a training owner. They are a follow-on media task, not a prerequisite for publishing the clearly labelled written reference.
