# Story readiness

Read AGENTS.md and the accepted story before editing. If client configuration or approval is missing, report it. Do not create or reorder backlog items or expand scope without product-owner permission.

1. Identify the user, need and measurable outcome.
2. Separate confirmed scope from assumptions, exclusions and dependencies.
3. Write observable acceptance criteria with IDs; include negative/error cases.
4. Cover security roles, data handling, accessibility, performance and cost where relevant.
5. Map each criterion to a feasible DEV verification method.
6. Flag unresolved decisions and split suggestions for human consideration.

Return a readiness assessment: ready, ready with explicitly approved exceptions, or blocked. List criterion IDs, proposed checks and questions for the owner. Do not build a blocked story.

Use docs/stories/story-template.md as the format.
