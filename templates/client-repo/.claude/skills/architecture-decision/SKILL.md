# Architecture decision

Read AGENTS.md, the problem statement and existing decisions. Distinguish facts, assumptions and recommendations. Do not claim approval or make tenant changes.

1. State the problem and decision boundaries.
2. Include a no-build or simpler existing-capability option where credible.
3. Compare maintainability, security, accessibility, integration, licensing, usage cost and ALM.
4. Cite current documentation for capability/licensing claims and flag uncertainty.
5. Recommend an option with explicit trade-offs, risk and verification.
6. Name the required human decision owner and record status as proposed until approved.
7. Record supported platform placement, preview/ALM limits, identity separation, approved tool authority and applicable AI/operational gates. Compare both coding agents under the same criteria; neither is preferred.

Use docs/adr/decision-template.md. Ask the licensing-cost-check skill to examine uncertain licensing or consumption assumptions.
